# تقرير مناسكنا إلى نسك — متطلبات الانضمام والتكامل

**النسخة:** 2.9.1+33  
**الهدف:** تزويد نظام نسك بتقرير تفصيلي عن تطبيق مناسكنا، ومحتوياته، وما يحتاجه التطبيق للانضمام إلى نسك، وما يجب أن يقدمه نسك حتى يتم التكامل الرسمي.  
**القاعدة الحاكمة:** لا ربط Legacy/ASP، ولا تفعيل تسجيل دخول في مرحلة التطوير الحالية، ولا استخدام بيانات حقيقية قبل إغلاق الحوكمة.

---

## 1. الملخص التنفيذي

**مناسكنا** هو تطبيق الهاتف والويب للحاج والمعتمر، ويمثل واجهة المواطن/الحاج فوق نظام **نسك**.  
**نسك** هو النظام الإداري والتشغيلي السيادي داخل PalWakf لإدارة الحج والعمرة.

```text
نسك = الإدارة والتشغيل ومصدر الحقيقة
مناسكنا = تطبيق الحاج والمعتمر وواجهة الخدمة
```

التطبيق الآن جاهز كـ **Internal Beta Ready** من ناحية البنية والاختبارات، لكنه لا يصبح تشغيليًا رسميًا إلا بعد تجهيز عقود الربط، المحتوى المعتمد، وسياسات الخصوصية.

## 3. ما يحتاجه مناسكنا من نسك

### 3.1 هوية الحاج وملفه

| الحقل | الاستخدام |
|---|---|
| pilgrim_id | معرف داخلي غير حساس |
| national_id_masked | عرض جزئي فقط عند الحاجة |
| full_name | بياناتي والبطاقة |
| gender | تخصيص أحكام ومحظورات الإحرام |
| age_group | كبار السن والحالات الخاصة |
| health_flags | إرشادات عامة دون تشخيص |
| company_id / group_id | المجموعة والمشرف |
| supervisor_contact | هواتف ضرورية والطوارئ |
| season_id | ربط بالموسم الحالي |

### 3.2 حالة الرحلة
- المرحلة الحالية.
- الخطوة التالية.
- نسبة الجاهزية.
- نوع الحج إن كان محددًا.
- حالة الوثائق والتطعيم والسكن والنقل.
- مواعيد التفويج ونقطة التجمع.
- تعليمات عاجلة.

### 3.3 الوثائق
- جواز السفر.
- التطعيمات.
- التصريح.
- بيانات الطوارئ.
- وثائق السكن والنقل.

### 3.4 الشكاوى والاستبيانات
- إنشاء شكوى.
- تصنيفها حسب المرحلة والخدمة.
- تحديد الأولوية.
- متابعة الحالة.
- تعبئة استبيان الحج.
- حفظ التقييمات وربطها بالشركة/الخدمة.

### 3.5 الإشعارات
- إشعارات عامة.
- إشعارات مخصصة.
- تعليمات شركة/مجموعة.
- تنبيهات التفويج والطوارئ.
- إشعارات اعتماد/رفض/تحديث.

## 4. ما يحتاجه نسك من مناسكنا

- إرسال بيانات منظمة فقط: `user_context`, `season_id`, `stage_id`, `service_key`, `request_type`, `payload`.
- احترام RLS/RBAC وترك الصلاحيات السيادية داخل نسك.
- عدم وضع بيانات حساسة داخل QR.
- عدم إرسال الموقع إلا بموافقة واضحة.
- عدم تفعيل الميكروفون إلا بضغط المستخدم.
- عدم رفع وثائق حقيقية قبل اعتماد Storage/RLS.
- تسجيل أحداث مهمة لاحقًا: فتح بطاقة، إرسال شكوى، إرسال استبيان، مشاركة موقع، إحالة للجنة الشرعية.

## 7. بوابات الانضمام الرسمي إلى نسك

لا يُعتمد انضمام مناسكنا إلى نسك إلا بعد:

1. نجاح اختبارات Flutter.
2. إغلاق تدقيق UX.
3. اعتماد المحتوى الشرعي الحساس.
4. اعتماد سياسة الخصوصية.
5. تجهيز عقود API/RPC.
6. تجهيز RLS.
7. تجهيز صفحة إدارة محتوى الحج داخل نسك.
8. اختبار الاتصال بوضع Preview دون بيانات حقيقية.
9. اختبار Android/Web على الأقل.
10. إنشاء Session Handoff واضح.
