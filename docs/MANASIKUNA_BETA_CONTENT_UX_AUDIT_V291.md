# Beta Content & UX Audit — مناسكنا v2.9.1

**النسخة:** 2.9.1+33  
**خط الأساس:** v290 — Beta Readiness Batches 05–11  
**نتيجة آخر اختبار معلنة:** All tests passed على v290  
**النطاق:** مراجعة المحتوى والواجهات صفحة بصفحة قبل الربط الحقيقي مع نسك أو بناء APK تجريبي.  
**قاعدة التطوير:** لا تسجيل دخول حاليًا، ولا بيانات حقيقية، ولا ربط Legacy/ASP.

---

## 1. قرار التدقيق

مناسكنا أصبح جاهزًا للدخول في **Beta Content & UX Audit** بوصفه تطبيقًا داخليًا مستقرًا من ناحية الاختبارات.  
الغرض من هذه المرحلة ليس إضافة صفحات كثيرة جديدة فقط، بل تثبيت جودة الصفحات الموجودة، وتحديد ما يلي لكل صفحة:

- هل المحتوى واضح للحاج؟
- هل الصفحة مناسبة لكبار السن؟
- هل يوجد خطر فتوى أو توجيه حساس؟
- هل تحتاج الصفحة بيانات من نسك؟
- هل تحتاج اعتماد اللجنة الشرعية؟
- هل تحتاج صلاحيات أو موافقات خصوصية؟
- هل يجب اختبارها على Web / Android / iOS؟
- هل تعمل حاليًا في وضع الضيف دون تسجيل دخول؟

---

## 2. منهجية تدقيق الصفحات

| المحور | سؤال التدقيق |
|---|---|
| UX | هل الشاشة واضحة ومقروءة، والزر الأساسي ظاهر، ولا يوجد ازدحام؟ |
| المحتوى | هل النص مختصر، متوسط، غير متشدد، وغير متساهل؟ |
| الشرعي | هل توجد فتوى أو حكم حساس يحتاج اعتماد اللجنة الشرعية؟ |
| الصحي | هل النص إرشادي فقط ولا يعطي تشخيصًا طبيًا؟ |
| الميداني | هل توجد تعليمات سلامة وزحام وموقع ومشرف؟ |
| نسك | هل الصفحة تحتاج بيانات من نسك لتصبح تشغيلية؟ |
| التقنية | هل الصفحة تدعم Web/Android/iOS والصوت/الموقع عند الحاجة؟ |

## 4. نقاط التحسين قبل APK تجريبي

1. تشغيل `flutter clean && flutter pub get && flutter test`.
2. تدقيق بصري على جهاز Android فعلي.
3. فحص TTS وSpeech-to-Text على Chrome وAndroid وiOS لاحقًا.
4. مراجعة النصوص الشرعية الحساسة عبر اللجنة الشرعية.
5. تجهيز خصوصية الموقع والميكروفون قبل الربط الحقيقي.

## 5. قرار الانتقال التالي

بعد نجاح اختبار v291، تكون الخطوة التالية واحدة من مسارين:
